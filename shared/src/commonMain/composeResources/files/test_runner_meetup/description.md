Выступление о разработке Test Runner — desktop-инструмента для автоматизации тестирования Android-приложений — и об опыте построения процесса вайб-кодинга с Claude и Claude Code при его создании.

## О чём рассказал

**Продуктовая часть.** Test Runner — приложение, которое управляет полным циклом прогонов тестов на Android-устройствах и эмуляторах: автоматически поднимает эмуляторы, запускает выбранные проверки и отправляет отчёты в TestIT. Решает проблему ручного смоук-тестирования, которое отнимало много времени тестировщиков и требовало целевого оборудования (конкретная версия ОС, рут/системные привилегии), которого не всегда было в наличии.

Показал на конкретном кейсе (проверка автообновления): ручная проверка занимала около 20 минут, с Test Runner это сводится к 5 секундам работы.

Разобрал архитектуру приложения (ядро, интерфейс, скрипты, конфигурации, каталог тестов) — устроена так, что добавление нового теста не требует правок основного кода.

**Часть про работу с AI.** Рассказал методологию, которую выстроил в процессе разработки:
- Разделение ролей между моделями: Claude (веб, Opus 4.8) — для проработки технического задания, поиска нюансов и пробелов, генерации дизайн-спецификаций по референсам; Claude Code (Sonnet 4.8) — для написания и рефакторинга кода. Мощная модель — там, где нужно думать, более простая — там, где нужно писать код, что снижает расход токенов.
- Поэтапную генерацию кода: сначала скелет приложения одним запросом по полному ТЗ (дал ~35% итогового объёма кода), затем — наращивание функционала отдельными блоками с проверкой после каждого шага.
- Эксперимент с делегированием архитектурных решений: сознательно не указывал модели, как раскладывать код по модулям и какие паттерны применять, задав только стек (PyQt6, bash, JUnit XML). Архитектура получилась рабочей и не переусложнённой.
- Минимальный набор инструментов сверх Claude/Claude Code (единственный MCP-сервер — context7 для документации по библиотекам) — и что больший эффект на практике дали не дополнительные тулы, а промпт-инжиниринг, качественный CLAUDE.md/README.md и явные ограничения контекста.

## Результаты и цифры

- Реализация проекта заняла около недели.
- В среднем около 200к токенов Sonnet на реализацию одного раздела функционала.
- Test Runner покрывает 23 тест-кейса через 6 скриптов (11 парных сценариев, 12 одиночных).
- Инструмент забирает на себя порядка 50% рутинных действий при смоук-тестировании, экономя около 40 минут ручной работы на один тест-план.
- С помощью инструмента были обнаружены баги, ранее не замеченные при ручном тестировании (например, проблема с обновлением на Android 12+ с системными привилегиями).

Доклад сопровождался живой демонстрацией работы приложения.
